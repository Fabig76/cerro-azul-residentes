### 4.2 · HTML — botón + scripts

En el `<header>` de `index.html`:

```html
<button type="button" class="tema-toggle" id="temaToggle"
        aria-label="Cambiar tema claro u oscuro" title="Cambiar tema">
  <svg class="icono-luna" ... aria-hidden="true">
    <path d="M21 12.79A9 9 0 1 1 11.21 3 7 7 0 0 0 21 12.79z"/>
  </svg>
  <svg class="icono-sol" ... aria-hidden="true">
    <circle cx="12" cy="12" r="5"/>
    <line ... /> ... (8 rayos)
  </svg>
</button>
```

**Decisión de diseño:** SVG en lugar de emoji 🌙/☀️. La visión del navegador
no distingue bien los emojis contra fondo claro (luna blanca invisible).
SVG con `stroke="currentColor"` cambia de color automáticamente según el
`tema`, sin importar el render del SO.

Script **anti-FOUC** en `<head>` (lee localStorage / prefers-color-scheme
del SO antes de que el CSS termine de cargar):

```html
<script>
  (function() {
    try {
      var guardado = localStorage.getItem('cerro-azul-tema');
      var prefiSO = window.matchMedia &&
                    window.matchMedia('(prefers-color-scheme: dark)').matches;
      var tema = guardado || (prefiSO ? 'oscuro' : 'claro');
      document.documentElement.setAttribute('data-tema', tema);
    } catch (e) { /* sin localStorage: queda en claro */ }
  })();
</script>
```

**Por qué en `<head>`:** sin este script, el usuario vería un flash blanco
de medio segundo al cargar la página cuando su preferencia es oscuro.
Aplicar `data-tema` antes del primer paint elimina el FOUC.

Handler del botón antes de `</body>`:

```html
<script>
  (function() {
    var btn = document.getElementById('temaToggle');
    if (!btn) return;
    btn.addEventListener('click', function() {
      var html = document.documentElement;
      var actual = html.getAttribute('data-tema') === 'oscuro' ? 'oscuro' : 'claro';
      var nuevo = actual === 'oscuro' ? 'claro' : 'oscuro';
      html.setAttribute('data-tema', nuevo);
      try { localStorage.setItem('cerro-azul-tema', nuevo); } catch (e) {}
      btn.setAttribute('aria-label', nuevo === 'oscuro'
        ? 'Cambiar a tema claro' : 'Cambiar a tema oscuro');
    });
  })();
</script>
```

Meta `theme-color` dual para barra del navegador móvil:

```html
<meta name="theme-color" content="#0066CC" media="(prefers-color-scheme: light)">
<meta name="theme-color" content="#0F1419" media="(prefers-color-scheme: dark)">
```

## 6 · Bug encontrado durante implementación (lección aprendida)

**Síntoma:** En el primer intento, usé emojis 🌙/☀️ dentro de `<span>`.
Verificación con PIL/Python reveló que el emoji luna 🌙 (color blanco/amarillo)
es prácticamente **invisible** contra el fondo claro del botón en modo claro
(217 píxeles del icono desaparecen contra el fondo blanco).

**Causa:** los emojis de luna típicos son blanco/amarillento claro; el fondo
del botón en modo claro también es claro.

**Fix:** reemplazar `<span>🌙</span>` y `<span>☀️</span>` por SVGs inline
con `stroke="currentColor"`. Ahora el color del icono sigue la variable
`color` del botón, que cambia según el tema.

**Lección #19:** en el rediseño visual (commit 0f1d6ce) se usó `:has()`
(CSS3) — en navegadores pre-2023 se ven como casillas normales. **No usar
emojis como íconos de UI** cuando el color de fondo puede cambiar entre
modos; usar SVG con `currentColor` en su lugar.
