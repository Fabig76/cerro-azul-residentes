## Lecciones aprendidas

### 1. Errores de digitación en Sheet externo
El Sheet 02 del operador es un archivo manual, no controlado por el
backend. Quien lo digitó asignó múltiples matrículas consecutivas
al mismo apto, omitiendo los intermedios.

El sistema Cerro Azul SÍ valida unicidad de apto en el Sheet Registros
(226 registros, 0 duplicados), pero NO controla el Sheet externo.

### 2. Validación cruzada por análisis de patrones
Para validar datos de un Sheet externo, comparar contra patrones
esperados (secuencias, distribuciones, sumas). En este caso, las
matrículas consecutivas (5461642-5461826) revelaron los aptos
intermedios faltantes.

### 3. Deploy drift es un riesgo crítico
El V35 en producción tenía 576 líneas más que el V35 en el repo. Si
hubiera deployado el V36 mal generado, hubiera roto el sistema de
tokens admin/vigilante. Lección: SIEMPRE tomar como base el archivo
desplegado, no el del repo local.

### 4. gviz/tq puede omitir contenido
Inicialmente clasifiqué 17 matrículas como "vacías" usando curl+gviz/tq.
La API oficial de Sheets (v4) reveló que tenían formato "01N-XXXX".
SIEMPRE usar la API oficial cuando el contenido parezca sospechoso.
